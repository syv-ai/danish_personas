# Persona prompt format

## Generation contract 5

Each record is generated by one OpenAI-compatible request. The strict response object
contains the structured attributes and the final Danish `persona`; the pipeline then
stores the same flat Parquet columns as before. Validation failures may trigger a
bounded retry, but a valid first response means exactly one provider request per
persona. Generation contract 5 uses validator `persona-safety-v19`. The release
manifest remains schema 2; the evidence schema is 3 because its prompt provenance
now has one combined prompt checksum.

## Provider input boundary

The single request receives only approved human-readable fields: municipality, the
official Danish `origin_country_da`, sampled legal `marital_status`, and reviewed
job-function labels and title allowlist entries. It never receives the origin code,
English origin label, contract metadata, or resolution fields. The English label
remains source/audit provenance but is withheld from the provider payload. The Danish
label is not ethnicity, citizenship, residence, or appearance, and origin cannot drive
culture, religion, job, interests, personality, family details, or visual traits.

The payload also supplies sampled legal `marital_status` and compatible personality
wording. Marital status is separate from the generated current relationship: the
response records a partnered/not-partnered status, male/female partner gender, and a
married/separated detail where the sampled legal category is combined. Same-gender
combinations are allowed without naming or inferring an orientation. OCEAN inputs are
cautious tendencies rather than diagnoses, abilities, or fixed traits.

## Detailed `persona`

The validator requires 300-900 characters across at least four sentences. The prose
must preserve age, the supplied `han` or `hun`, municipality, official Danish origin
label, education level, and current title or status. It must also use at least two
generated interests, one generated skill, one compatible personality tendency, and
any generated ambition.

The prompt asks for a concrete synthetic portrait written with `han` or `hun`,
without names, and including education detail, a workplace type and area, leisure
activities, relationships or family, and a dream or plan. Surnames, real employer or
institution names, exact addresses, contact details, appearance, and sensitive
attributes remain prohibited.

For the pooled `secondary_or_vocational` source category, the model must choose one
synthetic branch for the persona: either a `ungdomsuddannelse` or an
`erhvervsuddannelse`, with a plausible direction and town. This detail is invented; it
must not be represented as observed Statistics Denmark data.

Exact duplicate persona text is rejected across an output population. Checkpoints
retain checksum, accounting, tamper, and resume gates. Rejected completion text is not
persisted.

## Image use and review

`persona` is ordinary grounded prose, not an image prompt or visual description.
Downstream image generation is outside this contract and requires separate blinded
human review.
